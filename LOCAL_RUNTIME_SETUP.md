## Maple Table Placement

`pick_and_place_maple_table` is built in under `isaaclab_arena_environments`.
The object placements are generated by the Arena placement solver/placement pool on reset.
Without `--seed` or `--placement_seed`, repeated runs of the same setting can place objects differently.

For reproducible placement, add for example:

```powershell
--seed 42 `
--placement_seed 42 `
```

## Multi-Robot Async GR00T Demo

The async demo uses one vectorized Isaac Stage, one G1 workcell per environment, and one serial B=1
GR00T worker. Deadlines use control/simulation time, not slow Isaac Sim wall time:

```text
deadline window = async_prefetch_lead_steps * async_step_dt
default measured window = 25 * 0.02 s = 0.5 simulated seconds
```

Set the runtime environment in PowerShell:

```powershell
$env:OMNI_KIT_ACCEPT_EULA = 'Y'
$env:ISAACLAB_ARENA_FORCE_EXIT_ON_COMPLETE = '1'
$env:PYTHONPATH = 'C:\Projects\isaac\submodules\Isaac-GR00T;C:\Projects\isaac'
```

Visible six-robot saturation demo with HUD, overview camera, metrics, and viewport video:

```powershell
& C:\Isaac\envs\arena-py311\python.exe `
  C:\Projects\isaac\isaaclab_arena\evaluation\policy_runner.py `
  --viz kit `
  --experience C:\Projects\isaac\submodules\IsaacLab\apps\isaaclab.python.rendering.kit `
  --policy_type isaaclab_arena_gr00t.policy.gr00t_remote_closedloop_policy.Gr00tRemoteClosedloopPolicy `
  --policy_config_yaml_path isaaclab_arena_gr00t/policy/config/g1_locomanip_gr00t_closedloop_config.yaml `
  --remote_host 127.0.0.1 --remote_port 5555 `
  --scheduler async_edf `
  --async_prefetch_lead_steps 25 --async_step_dt 0.02 `
  --async_metrics_path eval/async_vla_demo/n6_saturation.json `
  --num_steps 180 --num_envs 6 --env_spacing 20 --enable_cameras `
  --video --video_dir eval/videos/async_vla_n6_saturation_run1 `
  galileo_g1_locomanip_pick_and_place `
  --object brown_box --embodiment g1_wbc_joint --overview_camera
```

For a capacity run without the HUD or video overhead, change `--num_envs` and the metrics filename,
remove `--video`, and add `--no-async_status_ui`. Summarize completed runs with:

```powershell
& C:\Isaac\envs\arena-py311\python.exe `
  isaaclab_arena_gr00t/scripts/summarize_async_capacity.py `
  eval/async_vla_demo/n2_smoke.json `
  eval/async_vla_demo/n4_capacity.json `
  eval/async_vla_demo/n5_saturation.json `
  eval/async_vla_demo/n6_saturation.json
```

Observed on the local RTX 5090 with one 480x640 policy camera per robot:

```text
N=2: zero miss, inference p95 0.125 s
N=4: zero miss, inference p95 0.137 s, virtual queue p95 0.297 s
N=5: first overload, 1 miss / 13 reached deadlines, hold 0.06 simulated seconds
N=6: 2 misses / 16 reached deadlines, hold 0.38 simulated seconds, max virtual queue 0.698 s
```

The measured zero-miss capacity for the tested `0.5 s` deadline is therefore four robots; five is
the first observed overloaded count. Re-run the sweep after changing camera count, image resolution,
prefetch lead, checkpoint, TensorRT mode, or network delay.

### Full six-robot episode with trace and status video

The clean overview hides the Galileo wall and door render geometry while preserving physics. This
command records a full 30 simulated seconds (`1500 * 0.02 s`) and writes one scheduler trace row per
control step:

```powershell
& C:\Isaac\envs\arena-py311\python.exe `
  C:\Projects\isaac\isaaclab_arena\evaluation\policy_runner.py `
  --viz kit `
  --experience C:\Projects\isaac\submodules\IsaacLab\apps\isaaclab.python.rendering.kit `
  --policy_type isaaclab_arena_gr00t.policy.gr00t_remote_closedloop_policy.Gr00tRemoteClosedloopPolicy `
  --policy_config_yaml_path isaaclab_arena_gr00t/policy/config/g1_locomanip_gr00t_closedloop_config.yaml `
  --remote_host 127.0.0.1 --remote_port 5555 `
  --scheduler async_edf `
  --async_prefetch_lead_steps 25 --async_step_dt 0.02 `
  --async_metrics_path eval/async_vla_demo/n6_full_episode/metrics.json `
  --async_trace_path eval/async_vla_demo/n6_full_episode/trace.json `
  --num_steps 1500 --num_envs 6 --env_spacing 20 --enable_cameras `
  --video --video_dir eval/videos/async_vla_n6_full_episode `
  galileo_g1_locomanip_pick_and_place `
  --object brown_box --embodiment g1_wbc_joint --overview_camera --clean_overview
```

`RecordVideo` captures only the 3D viewport. Render the saved trace into the MP4 and create a timeline
with:

```powershell
& C:\Isaac\envs\arena-py311\python.exe `
  isaaclab_arena_gr00t/scripts/render_async_status_video.py `
  --input-video eval/videos/async_vla_n6_full_episode/rl-video-step-0.mp4 `
  --trace eval/async_vla_demo/n6_full_episode/trace.json `
  --output-video eval/videos/async_vla_n6_full_episode/rl-video-step-0-status.mp4 `
  --timeline eval/async_vla_demo/n6_full_episode/timeline.png
```

The overlay uses green for execution, yellow for queued requests, blue for inference or gated results,
and red for deadline misses / joint-position hold. `metrics.json` contains aggregate and per-environment
timings; `trace.json` contains the state, queue depth, active inference environment, and deadline
countdown for every control step.

Galileo wall and door render geometry is hidden automatically for this recording mode; collision and
physics are unchanged. The observer cameras add rendering work, so this is a visualization run, not a
capacity benchmark.

  --policy_config_yaml_path isaaclab_arena_gr00t/policy/config/g1_locomanip_gr00t_closedloop_config.yaml `

request is being served; gray is idle. These intervals use simulated control time derived from measured
inference wall time, matching the deadline and queue model rather than slow Isaac Sim wall-clock playback.
